# Migration parity status

The TanStack application implements every legacy user-facing route. Collection creation now opens inline; legacy `/collection/:name/new` URLs redirect into that state. Legacy `/collection/:name/edit/:path` URLs redirect to their replacement routes.

Implemented product areas include authentication and account linking, repository/branch selection and creation, configuration/history, collection list/tree/search/sort/pagination, structured and raw content, root lists, nested fields and blocks, references, entry/file history and mutations, media browsing, uploads, folders, file moves and renames, deletion and private previews, actions/runs, collaborators/invitations, cache controls, settings/installations, administration, GitHub App installation, and signed webhook invalidation.

The repository dropdown closes at selection, before routed navigation completes. View on GitHub is followed by a separator and the branch submenu. Administration links live in the sidebar's Admin block and are hidden for invitation-backed access. A branch submenu shows up to five branches, prioritizing current/default branches and then GitHub's listing order. A loading message appears while additional branches load; known branches remain selectable. Manage branches searches the complete paginated list and permits GitHub users to create a valid, non-existing branch from the current branch; server permissions still govern creation and navigation. The legacy branch listing did not include latest-commit timestamps or latest-edit ordering.

The old Next.js UI called many `/api/:owner/:repo/...` JSON routes as an internal transport. Repository history contains no public documentation or non-legacy consumer for those shapes, so the replacement uses a validated JSON API through the same access-policy gateway. The externally meaningful HTTP routes retained are Better Auth, app version, GitHub App installation, GitHub webhook, health, and authenticated media preview.

Configuration uses the same source validator in the editor and on save: errors block saving, unknown-property warnings do not. Raw YAML is preserved, including warning-only properties; those properties do not become supported settings. Invalid, recursive, and excessively expanded YAML aliases produce diagnostics rather than escaping into the page error boundary.

## Built-in field behavior

Structured saves validate normalized values before removing empty output values. Client and server share indexed validation paths for nested objects, selected blocks, field lists and root lists. Errors appear beside controls, open collapsed list items and focus the first invalid control; hidden/unavailable fields have a form-level fallback. An empty list row must be completed or explicitly removed, so clearing a value never silently deletes its row or bypasses a minimum count. Zero and false remain valid values.

Select/reference/file/image multiple values compose with field lists. Saved reference objects retain their label while resolution is unavailable, then use the current label; writes normalize to scalar values or scalar arrays. Explicit numeric strings and boolean `true`/`false` strings are normalized; ambiguous boolean strings are rejected. Invalid stored dates remain visible for correction and fail validation on save. Native scalar/text/selection read-only controls permit inspection without mutations. Inherited locks also apply inside nested lists, including draft comparisons and in-flight mutations. `list.default` takes precedence over a scalar default.

Reference options use configured nested primary fields, indexed template paths, escaped braces, field read transforms and filename dates. Browsing returns at most 100 matches from 50 directories per request with explicit continuation. Selected default `{path}` values resolve from their cached parent directories rather than rescanning unrelated folders; custom value templates continue across pages until selections resolve or the collection ends. Tree-node enrichment is retained when subfolders are disabled. This does not add a GitHub identity-translation request.

Media upload completion and partial failures preserve repeated selections unless `unique: true` is configured. Rich-text image controls restrict mixed media libraries to image extensions. Markdown preview rewriting preserves balanced destination parentheses, nested alt brackets and titles, and skips inline/fenced code examples. Collection cells show file basenames/icons/counts, select labels, reference fallback labels, boolean/date list counts, and configured datetime values with their time. Textareas forward native minimum and maximum lengths.

Generic remote endpoint fetching, creatable options, option artwork and configurable object-preserving reference writes were removed from the legacy implementation before the rewrite. They remain deferred in TODO; accepting older `{value,label}` shapes does not re-enable those features. External custom modules use the split registration/edit/view contracts and require a source port, documented in the [custom-field migration map](../../src/fields/custom/README.md#porting-a-version-2-field). Literal/callable defaults, built-in overrides, nested read/write hooks with repository configuration and schema coercion ordering have conformance coverage. Formatted dates in explicit defaults are normalized recursively through lists, objects and selected blocks. This contract coverage does not claim acceptance of arbitrary third-party UI code or replace built-in field browser acceptance.

Reusable component definitions resolve independently of declaration order. Circular references report their chain instead of exhausting the call stack.

Repository-root collections and media use an empty relative path; single-character directory names are valid. Field file-type restrictions intersect the library's restrictions: no overlap means no files are selectable or uploadable, while an unconfigured restriction remains unrestricted.

## Mutation notifications

Completed writes use one concise Sonner success notification; validation and operation failures remain inline. Navigation, filters, search and ordinary data refreshes do not show success notifications. Action notifications confirm a run, rerun or cancellation request rather than workflow completion.

Media uploads use one notification per batch, updated with the current file number and the confirmed upload count. Uploads stop at the first failure; successfully uploaded files remain available and selected, and the failed batch notification can be dismissed. The Upload control keeps its label and shows a spinner while the batch runs. Rich-text image placeholders never enter persisted Markdown or HTML as temporary blob URLs; a failed preview does not discard a successfully uploaded permanent URL.

Select and reference fields use searchable shadcn comboboxes, with removable chips for multiple values. Existing string/array values, missing-option fallbacks, read-only state and selection limits are preserved. References retain debounced server search and selected-label resolution; search does not remove existing selections. Cache management remains opt-in through `settings.cache: true`. Action definitions and tracked runs use the selected branch, with an explicit workflow ref able to target a different branch.
